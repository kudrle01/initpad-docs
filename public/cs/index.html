Nápověda InitPad

Veřejná edice propojená s GitHubem a self-hosted instalace. Popisuje verzi 0.2.36.

1. Začínáme

InitPad za vás založí repozitář se základem aplikace a hotovou pipeline a po každém pushi aplikaci sestaví, otestuje a nasadí na váš server. Vy píšete kód, Docker ani CI nastavovat nemusíte.

Dvě edice

InitPad existuje ve dvou edicích. Většina této nápovědy platí pro obě, rozdíly jsou vždy uvedené u textu.

Veřejná edice (GitHub)Self-hosted edice
Kde běžíProvozuje ji autor InitPadu na adrese https://staging.initpad.me (zatím zkušební provoz).Na vašem serveru. Adresu určí správce při instalaci, například http://localhost:8080 nebo https://initpad.skola.example.
PřihlášeníÚčtem GitHub.Uživatelským jménem a heslem, účty zakládá správce instance.

Kapitoly jen pro tuto ediciPřihlášení, Propojení GitHubu, Omezení veřejné ediceSelf-hosted InitPad

Co budete potřebovat

  • ve veřejné edici účet na GitHubu, v self-hosted edici účet od správce instance,
  • Linux server s Dockerem, na kterém aplikace poběží (viz požadavky na server). Stačí mu odchozí přístup na adresu InitPadu, takže může stát za routerem i za VPN.

Cesta ve veřejné edici má pět kroků:

  1. Přihlaste se účtem GitHub.
  2. Nainstalujte GitHub App, aby InitPad směl pracovat s vašimi repozitáři.
  3. Připojte server jedním příkazem.
  4. Založte projekt ze šablony, nebo importujte existující repozitář.
  5. Pushněte změnu. InitPad ji nasadí do prostředí dev a vy ji pak povyšujete dál.

V self-hosted edici kroky 1 a 2 odpadají: přihlásíte se heslem a repozitáře vznikají ve vestavěné Gitee. Postup najdete v kapitole Self-hosted InitPad.

Nápověda v aplikaci
Odkaz Nápověda v levém menu otevře tuto stránku v jazyce, který máte v InitPadu nastavený. Odkazy Více v nápovědě u jednotlivých obrazovek vedou rovnou na příslušnou kapitolu. Přepínač jazyka nahoře zachová kapitolu, na které právě jste.

2. Přihlášení

Tato kapitola platí pro veřejnou edici. Přihlášení v self-hosted edici popisuje část Přihlášení heslem a aktivace účtu.

Na úvodní stránce zvolte Pokračovat přes GitHub. Účet v InitPadu vznikne při prvním přihlášení, heslo se nezakládá.

Přihlášení platí sedm dní. Po aktualizaci platformy se může stát, že se budete muset přihlásit znovu. Když mezitím vyjde nová verze InitPadu, otevřená karta ukáže InitPad byl aktualizován a novou verzi načtete tlačítkem Obnovit.

Verzi InitPadu, se kterou pracujete, vidíte vlevo dole pod svým účtem, například InitPad 0.2.36. Záložka otevřená během aktualizace se při dalším kliknutí sama jednou obnoví a načte novou verzi.

V Nastavení účtu najdete v části Přihlášené prohlížeče všechna zařízení, kde jste přihlášení. Prohlížeč, který nepoznáváte, odhlaste, případně zvolte Odhlásit všechny ostatní.

3. Propojení GitHubu

Tato kapitola platí pro veřejnou edici. Self-hosted edice GitHub nepoužívá.

InitPad s repozitáři nepracuje pod vaším jménem, ale přes GitHub App. Vidí jen účty a organizace, do kterých ji nainstalujete, a jen repozitáře, které jí povolíte.

  1. Otevřete Nastavení účtu a v části Účet GitHub zvolte Nainstalovat GitHub App. Otevře se okno GitHubu, proto povolte vyskakovací okna.
  2. Vyberte svůj účet nebo organizaci a rozhodněte, zda App uvidí všechny repozitáře, nebo jen vybrané.
  3. Po návratu se instalace objeví v seznamu pod vaším účtem. Další účet nebo organizaci přidáte tlačítkem Přidat instalaci.
Organizace
Instalaci do organizace musí potvrdit její vlastník. Pokud jím nejste, GitHub mu pošle žádost a Nastavení ukážou Čeká se, až vlastník organizace na GitHubu schválí aplikaci. Po schválení se organizace propojí sem. Jakmile vlastník App schválí a vy se vrátíte do okna InitPadu, organizace se připojí sama.

Samotné členství v organizaci nestačí. Repozitáře organizace uvidíte v InitPadu až po instalaci App do ní.

4. Připojení serveru

Aplikace neběží u InitPadu, ale na vašem serveru. InitPad umí dva druhy serverů:

Způsob připojeníPro coKdo ho smí přidat
InitPad Agent pro Docker (doporučeno)Všechny šablony. Na serveru běží malý program InitPad Agent, který si sám chodí pro práci. InitPad se na server nepřipojuje, takže nemusíte otevírat port pro správu ani předávat SSH klíč.Vlastník nebo administrátor workspace
Sdílený webhosting přes SFTPStatické weby a PHP (Nette, Laravel, Symfony) na běžném webhostingu. InitPad se k hostingu připojuje sám přes SFTP.Vlastník, administrátor nebo správce workspace

Server typu Agent smí přidat jen ten, kdo smí Agenta i připojit, tedy vlastník nebo administrátor workspace. Správce workspace smí přidat a ověřit SFTP server a používat všechny servery, které už workspace má. Ostatní role servery jen vidí.

Co server s Agentem potřebuje

  • Linux (amd64 nebo arm64) s Docker Engine běžícím pod rootem, tedy se socketem /var/run/docker.sock. Rootless Docker Agent nepodporuje. Grafické prostředí není potřeba.
  • Odchozí HTTPS spojení na adresu InitPadu. Příchozí porty potřebuje jen spravovaná brána (80 a 443).
  • Oprávnění root pro jednorázové spuštění instalátoru.

Instalátor před registrací zkontroluje velikost serveru. Pod minimem skončí s výpisem, co chybí, mezi minimem a doporučením jen varuje.

MinimumDoporučeno
RAM1,5 GB4 GB
CPU12
Volné místo pro Docker10 GiB20 GiB

Minimum stačí na Agenta a jedno prostředí, doporučená velikost na projekt s prostředími dev, test a prod. Každé prostředí má ve výchozím stavu limit 512 MB paměti a 1 CPU a při nasazení nové verze krátce běží stará i nová verze vedle sebe.

Postup pro server s Agentem

  1. Otevřete Servery a zvolte Přidat server.
  2. Jako Způsob připojení ponechte InitPad Agent pro Docker (doporučeno) a vyplňte Název.
  3. Zvolte Zpřístupnění aplikací (viz tabulka níže) a vyplňte Základní URL aplikací, u spravované brány Základní URL brány.
  4. V poli Umí spustit zaškrtněte runtimy, které má server nabízet. Šablonu půjde nasadit jen na server, který její runtime umí. Podporu Dockeru Agent po registraci potvrdí sám.
  5. Zvolte Přidat server. Otevře se dialog InitPad Agent; později ho otevřete u serveru tlačítkem Spravovat Agenta. Až budete u serveru, zvolte Vygenerovat registraci.
  6. 1. Instalace a registrace na Docker serveru: zkopírujte příkaz a spusťte ho v interaktivním terminálu na serveru. Ověří kontrolní součet instalátoru a image Agenta, zkontroluje velikost serveru a Agenta spustí. Tlačítko Jen stáhnout skript stáhne instalátor bez spuštění.
  7. 2. Registrační token: až si o něj instalátor řekne, vložte token. Zadává se skrytě, do historie shellu se nedostane. Token se zobrazí jen jednou, po zavření dialogu ho už neuvidíte, platí krátce a jen pro jedno použití.
  8. Po chvíli dialog ukáže Agent … je aktuální a server se v seznamu objeví jako připojený.
ZpřístupněníKdy ho zvolitAdresa aplikace
Přímé porty (lokálně / laboratoř)Zkoušení, laboratoř, server ve vnitřní sítiAdresa serveru a port, například http://192.168.1.50:32768. S Agentem 0.17 a novějším zůstává port stejný i po restartu kontejneru nebo serveru a leží v rozsahu 30000–32767, který stačí povolit ve firewallu.
Spravovaná brána (produkce)Produkce, stálé HTTPS adresyStálá adresa pro každý projekt a prostředí, například https://shop-prod-1a2b3c4d.apps.example.cz. Vyžaduje doménu, viz Spravovaná brána.
Server za VPN nebo doma
Funguje to. Agent navazuje jen odchozí spojení a po nasazení si sám ověří, že aplikace odpovídá. Aplikaci pak otevře jen ten, kdo se na server dostane, tedy typicky kdo je ve stejné síti nebo na stejné VPN.

Spravovaná brána

Brána dá každému prostředí stálou HTTPS adresu pod vaší doménou. Instalátor Agenta ji na serveru nastaví sám: soukromou certifikační autoritu (CA), TLS vstup na portech 80 a 443 a vnitřní bránu.

  1. Zvolte doménu pro aplikace, například apps.example.cz. Musí to být DNS jméno, ne IP adresa.
  2. V DNS nasměrujte na server dva záznamy: samotnou doménu apps.example.cz a wildcard *.apps.example.cz. Ve vnitřní síti je založte na svém DNS serveru.
  3. Na serveru a ve firewallu povolte příchozí porty 80 a 443. Nesmí je obsadit jiný webový server. Do aktivního ufw instalátor doplní potřebné pravidlo sám.
  4. Při přidání serveru zvolte Spravovaná brána (produkce) a jako Základní URL brány zadejte https://apps.example.cz.
  5. Spusťte instalační příkaz z dialogu Agenta. Obsahuje volbu --gateway-domain apps.example.cz a na konci vypíše otisk SHA-256 certifikátu CA.
  6. V dialogu Agenta v části Brána aplikací zvolte Otestovat bránu. Test jen čte: ověří wildcard DNS, důvěryhodné TLS na portu 443 a vnitřní bránu, žádnou routu nemění. Na server lze nasazovat, až test projde.
  7. Nainstalujte certifikát brány na počítače, ze kterých se aplikace otevírají.

Agent 0.16 a novější bránu po své aktualizaci obnoví sám. U staršího Agenta, nebo když se obnova nestala, spusťte na serveru příkaz ze sbalitelné části Obnovit bránu na serveru; registrační token k tomu není potřeba. Změna zpřístupnění nebo URL brány zruší výsledek testu a bránu je potřeba otestovat znovu.

Certifikát brány

Brána podepisuje HTTPS certifikáty aplikací vlastní CA. Prohlížeč jim bude důvěřovat, až tuto CA nainstalujete. Stačí to jednou na každý počítač.

  1. V dialogu Agenta v části Certifikát brány zvolte Stáhnout certifikát. Stáhne se soubor initpad-gateway-ca.crt z adresy http://apps.example.cz/initpad-ca.crt.
  2. Porovnejte otisk. Dialog ukazuje Otisk SHA-256. Před instalací ho porovnejte se staženým souborem:. Otisk souboru zjistíte příkazem openssl x509 -in initpad-gateway-ca.crt -noout -fingerprint -sha256. Dokud test brány neproběhl, otisk v dialogu chybí; porovnejte ho pak s otiskem, který vypsal instalátor.
  3. Certifikát nainstalujte podle systému:
    • Windows: otevřete soubor → Nainstalovat certifikát → Místní počítač → Důvěryhodné kořenové certifikační autority. Chrome a Edge pak certifikátu důvěřují také.
    • macOS: dvakrát klikněte na soubor, přidejte ho do Klíčenky (Systém) a v jeho nastavení důvěry zvolte Vždy důvěřovat.
    • Firefox (má vlastní úložiště certifikátů): Nastavení → Soukromí a zabezpečení → Zobrazit certifikáty → Autority → Importovat a zaškrtněte důvěru pro identifikaci webových stránek.
  4. Ověřte instalaci: restartujte prohlížeč a otevřete adresu nasazené aplikace. Prohlížeč nesmí hlásit nedůvěryhodný certifikát a v podrobnostech certifikátu uvidíte jako vydavatele CA InitPadu.

SFTP hosting

Na sdílený webhosting nasadí InitPad statické weby (React, Vue) a PHP aplikace (Nette, Laravel, Symfony). PHP navíc vyžaduje shellový přístup pod stejným účtem. Ostatní šablony potřebují server s Agentem.

Jen veřejně dosažitelný hosting
Na rozdíl od Agenta se k SFTP hostingu připojuje InitPad sám. Ve veřejné edici proto musí host i veřejná URL vést na veřejnou internetovou adresu; hosting za VPN, v domácí síti nebo na privátní adrese nepůjde přidat. Self-hosted instance se může připojit i k hostingu ve své vnitřní síti.
  1. V Servery zvolte Přidat server a jako Způsob připojení Sdílený webhosting přes SFTP.
  2. Vyplňte Název, Port (obvykle 22) a v Umí spustit zaškrtněte Static, případně PHP.
  3. Vyplňte Host, Uživatelské jméno a v poli Ověření zvolte Heslo, nebo SSH klíč a vložte soukromý klíč OpenSSH.
  4. Zvolte Získat otisk. InitPad načte veřejný klíč serveru, aniž by poslal heslo. Otisk porovnejte s hodnotou od správce hostingu a potvrďte Důvěřovat a uložit. Při každém dalším připojení InitPad vyžaduje přesně tento klíč.
  5. Vyplňte Vzdálená cesta (adresář webu, například /www/myapp) a Veřejná URL, na které je web vidět.
  6. Zvolte Přidat server a pak u serveru Otestovat připojení. Nasazovat lze jen na ověřený server.

Aktualizace Agenta a stav offline

Když vyjde nová verze Agenta, dialog Spravovat Agenta ukáže Je k dispozici Agent …. Agent 0.13 a novější se aktualizuje vzdáleně tlačítkem Nainstalovat aktualizaci: vymění se jen kontejner Agenta, aplikace běží dál, a když se nový Agent nepřihlásí, vrátí se předchozí. Agent přitom musí být online. Starší Agent dostane jednorázový ruční příkaz, který spustíte na serveru; identita serveru zůstane a nový token není potřeba.

Server je offline, když od Agenta 90 sekund nepřišel heartbeat. Dialog pak ukáže Agent je offline a čas posledního kontaktu. Úlohy bezpečně čekají ve frontě a po návratu Agenta pokračují; nasazení mezitím ukazuje Čeká se na Agenta. Ověřte, že server běží, Docker je spuštěný a server se dostane na adresu InitPadu. Když kontejner Agenta neběží, spusťte na serveru příkaz z části Znovu připojit Agenta v dialogu.

Odpojení, vyřazení a smazání serveru

U serveru je sekce Odpojení a smazání se třemi tlačítky:

TlačítkoCo udělá
Odpojit serverInitPad přestane server spravovat a zneplatní jeho přístup. Běžící aplikace zůstanou online.
Vyřadit serverPro server, který rušíte. Historie a adresy zůstanou viditelné a nasazení na něm pak půjde uvolnit.
Smazat serverOdebere server z InitPadu. Na samotném serveru se nic nesmaže.

Odpojený server jde smazat, jen když žádné jeho prostředí neeviduje nasazení. Jinak InitPad ukáže Nejdřív uvolněte nasazení na tomto serveru: …; nasazení uvolníte akcí Uvolnit nasazení, viz Nasazení a prostředí.

Odinstalace Agenta ze serveru

V dialogu Spravovat Agenta rozbalte Diagnostika a odebrání → Odinstalovat ze serveru a příkaz spusťte na serveru. Ověří kontrolní součet instalátoru, odmítne server registrovaný pro jiný cíl, vypíše, co odstraní, a vyžádá potvrzení. Odstraní kontejner Agenta, jeho uloženou identitu a certifikát InitPadu, který pro něj byl nainstalován. Sekce je dostupná i pro odpojeného Agenta. Spravovaná brána na serveru zůstane.

Volba Odstranit i aplikace, které InitPad na tento server nasadil smaže jejich kontejnery a sítě přímo na serveru. InitPad je pak dál zobrazuje jako nasazené, proto je raději odeberte v InitPadu, dokud je Agent připojený. Po odinstalaci Agenta v InitPadu odpojte, nebo server smažte, aby na něj InitPad už nečekal.

5. Nový projekt

  1. Zvolte Nový projekt a zadejte Název projektu: 2–41 malých písmen, číslic nebo pomlček, začíná písmenem. Název se použije i pro repozitář a adresu aplikace.
  2. Ve veřejné edici vyberte v poli Vlastník repozitáře na GitHubu účet nebo organizaci, kde má repozitář vzniknout. V self-hosted edici vznikne repozitář ve vestavěné Gitee.
  3. Vyberte Šablonu a Pipeline, tedy která prostředí projekt bude mít: dev, test a prod, jen dev a prod, nebo jen prod.
  4. V části Cíle nasazení přiřaďte každému prostředí server. Jeden server může hostit více prostředí. Server, který zatím nejde použít, má u sebe důvod, například Agent není připraven nebo kontrola gateway selhala.
  5. Zvolte Vytvořit projekt.

InitPad založí soukromý repozitář s kostrou aplikace, souborem Dockerfile a workflow pro CI a nastaví mu potřebné secrety. Stránka projektu pak ukazuje Projekt se připravuje… a po startu první pipeline Sestavuje se první verze…; obnovuje se sama. Po dokončení pipeline se aplikace nasadí do prostředí dev.

6. Import existujícího repozitáře

Na stránce Nový projekt zvolte Import existujícího repozitáře. InitPad při importu váš kód nemění. Repozitář ale musí splnit tři podmínky a InitPad je před importem sám zkontroluje:

PodmínkaPodrobnosti
DockerfileV kořeni výchozí větve. Čistě statické šablony ho nevyžadují.
Workflow InitPaduPřesně v souboru .github/workflows/ci.yml (veřejná edice), nebo .gitea/workflows/ci.yml (self-hosted). Startovní verzi si stáhnete na obrazovce importu a commitnete ji sami.
Název repozitáře2–41 malých písmen, číslic nebo pomlček, začíná písmenem. Stane se názvem projektu.

Projekt, který už má vlastní pipeline

  • Vaše workflow v jiných souborech běží dál beze změny.
  • InitPad čte stav jen z ci.yml. Pokud se tak jmenuje vaše pipeline, přejmenujte ji, nebo kroky InitPadu přidejte do ní.
  • Nasazení spouští jen workflow InitPadu. Když vaše testy v jiném souboru selžou, InitPad to nevidí a nasadí i tak. Testy, které mají nasazení zastavit, patří do ci.yml.

7. Nasazení a prostředí

Push do výchozí větve spustí pipeline. Ta aplikaci otestuje, sestaví image a předá ho InitPadu, který ho nasadí do prostředí dev. Do dalších prostředí se povyšuje přesně tentýž image, nic se nesestavuje znovu.

Co chceteJak na to
Povýšit dev do testuTlačítko se šipkou mezi kartami prostředí.
Nasadit do produkceŽádost o prod. Nasazení musí schválit vlastník, administrátor nebo správce workspace.

9. Tým, role a kvóty

Projekty, servery i instalace GitHub App patří do workspace. Kromě osobního workspace si můžete založit týmový v nabídce workspace v levém menu volbou Přidat nový workspace. Ve veřejné edici může jeden účet vlastnit nejvýše pět týmových workspace, v self-hosted edici limit ve výchozím stavu není.

Osobní workspace je jen váš. Členy přidáte do týmového workspace v Nastavení workspace (položka Workspace v menu) v části Členové workspace tlačítkem Přidat člena. Zadáte uživatelské jméno nebo e-mail. Ve veřejné edici se dotyčný musí do InitPadu aspoň jednou přihlásit, v self-hosted edici mu účet musí nejdřív založit správce instance.

Člen workspace má jednu z pěti rolí:

RoleCo smí navíc oproti předchozí
ČtenářProhlížet projekty, servery a jejich stav.
ČlenZakládat a importovat projekty, nasazovat a měnit proměnné.
SprávcePřidávat a ověřovat SFTP servery, upravovat servery, měnit pipeline projektu a schvalovat nasazení do produkce.
AdministrátorPřidávat servery s Agentem a připojovat Agenta, spravovat přístup workspace k serverům, instalovat GitHub App pro workspace a spravovat členy.
VlastníkMěnit pravidlo pro schvalování produkce.

Workspace může vyžadovat, aby produkci schválil někdo jiný než žadatel. Kdo co udělal, najdete v části Auditní log.

Kvóty workspace

Každý workspace má limity, které vidíte v Nastavení workspace v části Kapacita workspace. Zvýšit je může správce platformy.

Na každém serveru má workspace navíc vlastní limity: ve výchozím stavu nejvýše 50 prostředí a pro každé prostředí 1 CPU, 512 MB paměti a 256 procesů. Upravíte je u serveru tlačítkem Upravit přístup.

10. Přejmenování a smazání

Přejmenování repozitáře nebo organizace

Ve veřejné edici InitPad přejmenování na GitHubu sleduje sám. Projekt si do chvíle převezme nový název a další push se nasadí jako dřív. Kontejner na serveru si ponechá původní jméno, aby se běžící aplikace nepřesouvala.

Převod repozitáře
Převod na jiného vlastníka přejmenování není. Když repozitář přestane být pro instalaci GitHub App dostupný, InitPad ho považuje za smazaný a projekt uklidí.

Smazání projektu

  1. U každého prostředí nasazeného přes připojeného Agenta nejdřív zvolte Odstranit nasazení a počkejte, až úklid doběhne. Nasazení na odpojeném nebo vyřazeném serveru nejdřív uvolněte akcí Uvolnit nasazení, nebo je nechte označit v dialogu.
  2. Zvolte Smazat projekt.
  3. Volbu Smazat také zdrojový repozitář a uvolnit jeho název zaškrtněte jen tehdy, když chcete smazat i repozitář. Bez ní repozitář zůstane, jeho název zůstane obsazený a půjde ho později znovu importovat.

Projekt s nasazením na odpojeném nebo vyřazeném serveru jde smazat taky. Dialog toto nasazení označí server odpojen · zůstane na serveru a vyžaduje zaškrtnout Smazat záznam v InitPadu, i když chráněný úklid ještě čeká. Kontejnery tam mohou dál běžet a je potřeba je na serveru odstranit ručně.

Prostředí, jehož sestavení nebo nasazení selhalo dřív, než se na server cokoli dostalo, úklid nepotřebuje. Projekt s ním smažete rovnou.

12. Omezení veřejné edice

  • SFTP hosting musí být dosažitelný z internetu. Server za VPN nebo ve vnitřní síti připojte přes Agenta, pokud na něm běží Docker.
  • Zdrojem kódu je GitHub. Jiné Git servery veřejná edice nepodporuje.
  • Aplikace na serveru za VPN je dostupná jen z té sítě. InitPad ji ven nezveřejní.
  • Workflow InitPadu musí být v souboru .github/workflows/ci.yml.
  • Jeden účet může vlastnit nejvýše pět týmových workspace.

Self-hosted edice má jiná pravidla, viz Co v self-hosted edici platí jinak.

13. Self-hosted InitPad

Self-hosted InitPad běží celý na vašem serveru: web, API, databáze, Gitea s CI runnerem a úložiště artefaktů. Kapitola je pro uživatele i správce takové instance. Podrobný provozní návod je v repozitáři v deploy/README.md a deploy/OPERATIONS.md.

Instalace

Server pro InitPad potřebuje Linux s Docker Engine a pluginem Compose, minimálně 2 CPU, 6 GiB RAM a 20 GiB místa pro Docker (doporučeno 4 vCPU, 8 GiB a 40 GiB). Na Ubuntu 24.04 a novějším nejdřív spusťte sudo ./prepare-rootless-runner.sh; instalátor na to sám upozorní.

git clone https://github.com/kudrle01/initpad.git
cd initpad/deploy
./install.sh

Při prvním spuštění se instalátor zeptá, jak budou uživatelé InitPad otevírat:

VolbaKdyAdresa a HTTPS
Jen tento počítačVyzkoušení na vlastním počítačihttp://localhost:8080, bez HTTPS
Interní síť s DNSŠkola nebo firma, jména na vlastním DNS serveruNapříklad https://initpad.skola.example, vlastní certifikační autorita InitPadu
Veřejná doménaServer dostupný z internetu na portech 80 a 443Například https://initpad.example.org, certifikát Let's Encrypt
Místní síť přes IP adresuOd verze 0.2.36 (./install.sh --ip <adresa>). Laboratoř nebo virtuální počítač bez DNS, InitPad se otevírá přes IP adresu serveru.Adresa ve tvaru http://192.168.1.50:8080

U voleb s doménou potřebujete dva DNS záznamy na IP serveru: jméno platformy a jméno Gitu (například git.skola.example). Na konci instalátor vypíše adresu platformy, instalační token a u interní sítě otisk certifikátu. Skript lze kdykoli spustit znovu, doplní jen to, co chybí; doménu nebo režim změníte příkazem ./install.sh --reconfigure.

První administrátor

  1. Otevřete adresu platformy, kterou instalátor vypsal.
  2. Zvolte Vytvořit účet a vyplňte uživatelské jméno, e-mail, heslo (aspoň 12 znaků) a Instalační token z konce výpisu instalátoru.
  3. První účet se stane administrátorem platformy. Další účty zakládá on, viz níže.

Hláška The setup token is not valid. Use the token printed at the end of install.sh. znamená chybu v tokenu. Token je uložený v deploy/.env jako INITPAD_BOOTSTRAP_TOKEN.

Přihlášení heslem a aktivace účtu

Ve výchozím režimu se uživatelé sami neregistrují, účty zakládá administrátor:

  1. Administrátor otevře v levém menu Platforma a v části Uživatelé zvolí Přidat uživatele.
  2. Když má instance nastavený e-mail, odejde uživateli aktivační odkaz. Jinak se odkaz zobrazí jednou a administrátor ho předá bezpečnou cestou. Nový odkaz vytvoří akcí Nový aktivační odkaz; starý tím přestane platit.
  3. Uživatel otevře odkaz, na stránce Aktivujte svůj účet zvolí heslo (aspoň 12 znaků) a potvrdí Aktivovat a přihlásit se.
  4. Dál se přihlašuje na úvodní stránce uživatelským jménem nebo e-mailem a heslem. Přihlášení platí sedm dní.

Administrátor může heslo resetovat (uživatel dostane dočasné heslo, které musí při dalším přihlášení změnit) nebo účet deaktivovat; deaktivovaný účet se nepřihlásí do InitPadu ani do Gitey.

Gitea a Git

Repozitáře projektů jsou ve vestavěné Gitee na adrese Gitu, kterou vypsal instalátor (u lokální instalace http://gitea.localhost:3001). Do Gitey se přihlásíte účtem InitPadu přes jednotné přihlášení (SSO): na přihlašovací stránce Gitey zvolte přihlášení přes initpad-sso. Zvláštní heslo pro Giteu nezakládáte.

Pro práci z příkazové řádky otevřete Nastavení účtu → Připojit Git, zvolte Zobrazit příkaz pro nastavení a příkaz jednou spusťte v terminálu. Pak klonujete, stahujete i pushujete bez zadávání hesla. Příkaz uloží váš osobní token Gitey do ~/.gitconfig, proto ho nesdílejte.

Certifikát platformy

U instalace pro interní síť vydává InitPad HTTPS certifikáty vlastní certifikační autoritou. Aby prohlížeč InitPadu i Gitee důvěřoval bez varování, nainstalujte její certifikát jednou na každý počítač:

  • v InitPadu v Nastavení účtu → Certifikát platformy (soubor initpad-root-ca.crt, otisk SHA-256 a návod pro Windows, macOS a Firefox, stejně jako u certifikátu brány),
  • na počítači, který InitPadu ještě nedůvěřuje, přes HTTP z adresy http://<jméno platformy>/initpad-ca.crt; otisk porovnejte s výpisem instalátoru,
  • v doméně Windows ho správce rozdá skupinovou politikou do úložiště Důvěryhodné kořenové certifikační autority.

Servery s Agentem certifikát platformy dostanou automaticky: příkaz z dialogu Agenta ho stáhne, ověří otisk a nastaví ho jen pro registry InitPadu. Certifikát platformy a certifikát spravované brány jsou dva různé soubory.

Přístup workspace k serverům

Kromě vlastních serverů workspace (přidávají se stejně jako ve veřejné edici) může instance nabízet servery platformy, například vestavěný Docker na hostiteli InitPadu (Docker · přímý self-hosted). Workspace na nich smí nasazovat, až mu vlastník nebo administrátor workspace povolí přístup:

  1. V Servery u serveru s označením Pro tento workspace není povoleno zvolte Povolit pro ….
  2. Nastavte Povolené runtimy, Kvóta prostředí, limity CPU, paměti a procesů na prostředí a případně automatický úklid prostředí dev a test.
  3. Přístup lze později Upravit přístup, Pozastavit přístup nebo Odebrat přístup. Běžící aplikace to nezastaví.

Vestavěný Docker se hodí na vyzkoušení. U lokální instalace publikuje porty aplikací jen na tomto počítači. Pro aplikace dostupné z jiných počítačů použijte server s Agentem, ideálně se spravovanou bránou.

Stránka Platforma a aktualizace

Položku Platforma v levém menu vidí jen administrátoři platformy. Najdou tam správu uživatelů, kapacitu workspace a část Aktualizace platformy. Nainstalovanou verzi ukazuje i spodní část levého menu.

  1. V části Aktualizace platformy zvolte Obnovit, aby se načetl seznam podepsaných vydání.
  2. U novější verze zvolte Nainstalovat aktualizaci a potvrďte.
  3. InitPad zazálohuje databázi, vymění image API, webu a Supervisoru a ověří, že nová verze běží. Web a API se krátce restartují; aplikace v projektech se nerestartují.
  4. Když nová verze neprojde kontrolou, automaticky se vrátí předchozí a stránka ukáže Aktualizace na InitPad … se nedokončila. Běží předchozí verze.

Servery s Agentem se aktualizují zvlášť, viz Aktualizace Agenta.

Záloha a obnova

Zálohu dělá správce na serveru ve složce deploy příkazem ./backup.sh /bezpecna/cesta/initpad-backup. Záloha obsahuje databázi, repozitáře Gitey, artefakty, konfiguraci i přihlašovací údaje, proto ji zašifrujte a uchovávejte mimo server. Obnovu provádí ./restore.sh <adresář zálohy>; vyzkoušejte ji nejdřív na zkušební instalaci. Přesný postup, plánování a cvičnou obnovu popisuje deploy/OPERATIONS.md v částech Zálohy a Obnova.

Co v self-hosted edici platí jinak

  • Kapitoly Přihlášení a Propojení GitHubu neplatí. Přihlašujete se heslem, GitHub App ani pole Vlastník repozitáře na GitHubu nejsou.
  • Repozitáře jsou v Gitee, workflow je v .gitea/workflows/ci.yml a logy pipeline jsou v Gitee. Tlačítko pro opakování úloh na GitHubu není.
  • Sledování přejmenování a převodu repozitářů z kapitoly Přejmenování a smazání se týká jen GitHubu.
  • Limit pěti týmových workspace ve výchozím stavu neplatí. Kvóty workspace platí stejně.
  • SFTP hosting může být i ve vnitřní síti.
  • Nového člena workspace musí nejdřív založit administrátor platformy.
  • Odkazy Nápověda a Více v nápovědě vedou od verze 0.2.36 ve výchozím stavu na https://docs.initpad.me.
