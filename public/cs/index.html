Nápověda InitPad

Veřejná edice propojená s GitHubem. Popisuje verzi 0.2.32.

1. Začínáme

InitPad za vás založí repozitář se základem aplikace a hotovou pipeline a po každém pushi aplikaci sestaví, otestuje a nasadí na váš server. Vy píšete kód, Docker ani CI nastavovat nemusíte.

Budete potřebovat:

  • účet na GitHubu,
  • Linux server s Dockerem, na kterém aplikace poběží. Stačí mu odchozí přístup na internet, takže může stát za routerem i za VPN.

Celá cesta má pět kroků:

  1. Přihlaste se účtem GitHub.
  2. Nainstalujte GitHub App, aby InitPad směl pracovat s vašimi repozitáři.
  3. Připojte server jedním příkazem.
  4. Založte projekt ze šablony, nebo importujte existující repozitář.
  5. Pushněte změnu. InitPad ji nasadí do prostředí dev a vy ji pak povyšujete dál.
Nápověda v aplikaci
Odkaz Nápověda v levém menu otevře tuto stránku v jazyce, který máte v InitPadu nastavený. Odkazy Více v nápovědě u jednotlivých obrazovek vedou rovnou na příslušnou kapitolu.

2. Přihlášení

Na úvodní stránce zvolte Pokračovat přes GitHub. Účet v InitPadu vznikne při prvním přihlášení, heslo se nezakládá.

Přihlášení platí sedm dní. Po aktualizaci platformy se může stát, že se budete muset přihlásit znovu.

Verzi InitPadu, se kterou pracujete, vidíte vlevo dole pod svým účtem, například InitPad 0.2.32. Záložka otevřená během aktualizace se při dalším kliknutí sama jednou obnoví a načte novou verzi.

V Nastavení účtu najdete v části Přihlášené prohlížeče všechna zařízení, kde jste přihlášení. Prohlížeč, který nepoznáváte, odhlaste, případně zvolte Odhlásit všechny ostatní.

3. Propojení GitHubu

InitPad s repozitáři nepracuje pod vaším jménem, ale přes GitHub App. Vidí jen účty a organizace, do kterých ji nainstalujete, a jen repozitáře, které jí povolíte.

  1. Otevřete Nastavení účtu a v části Účet GitHub zvolte Nainstalovat GitHub App. Otevře se okno GitHubu, proto povolte vyskakovací okna.
  2. Vyberte svůj účet nebo organizaci a rozhodněte, zda App uvidí všechny repozitáře, nebo jen vybrané.
  3. Po návratu se instalace objeví v seznamu pod vaším účtem. Další účet nebo organizaci přidáte tlačítkem Přidat instalaci.
Organizace
Instalaci do organizace musí potvrdit její vlastník. Pokud jím nejste, GitHub mu pošle žádost a Nastavení ukážou Čeká se, až vlastník organizace na GitHubu schválí aplikaci. Po schválení se organizace propojí sem. Jakmile vlastník App schválí a vy se vrátíte do okna InitPadu, organizace se připojí sama.

Samotné členství v organizaci nestačí. Repozitáře organizace uvidíte v InitPadu až po instalaci App do ní.

4. Připojení serveru

Aplikace neběží u InitPadu, ale na vašem serveru. Na něm běží malý program InitPad Agent, který si sám chodí pro práci. InitPad se na váš server nikdy nepřipojuje, takže nemusíte otevírat žádný port pro správu ani předávat SSH klíč.

Co server potřebuje

  • Linux a běžící Docker,
  • odchozí HTTPS spojení na adresu InitPadu,
  • aspoň 1,5 GB RAM, 1 CPU a 10 GiB volného místa pro Docker. S menším serverem instalátor skončí ještě před registrací. Pod 4 GB RAM, 2 CPU nebo 20 GiB jen upozorní, že server může být na sestavování aplikací pomalý,
  • oprávnění správce pro jednorázové spuštění instalátoru.

Postup

  1. Otevřete Servery a zvolte Přidat server.
  2. Jako způsob připojení ponechte InitPad Agent pro Docker (doporučeno) a vyplňte název.
  3. V poli Umí spustit zaškrtněte runtimy, které server zvládne. Šablonu půjde nasadit jen na server, který její runtime umí.
  4. Zvolte Zpřístupnění aplikací, viz tabulka níže, a vyplňte veřejnou URL serveru.
  5. InitPad zobrazí příkaz Instalace a registrace na Docker serveru. Zkopírujte ho a spusťte na serveru. Instalátor se zeptá na registrační token, který vidíte ve stejném okně.
  6. Po chvíli se server v seznamu ukáže jako připojený.
ZpřístupněníKdy ho zvolitAdresa aplikace
Přímé portyZkoušení, laboratoř, server ve vnitřní sítiAdresa serveru a port. Port se při novém nasazení může změnit.
Spravovaná bránaProdukceStálá adresa pro každý projekt a prostředí. Vyžaduje vlastní doménu směrovanou na server.

Spravovaná brána

U spravované brány instalační příkaz nastaví zároveň bránu pro vaši doménu: soukromou certifikační autoritu, TLS vstup a samotnou bránu. Předem v DNS nasměrujte doménu i *.doména na server.

HTTPS certifikáty aplikací vydává tato soukromá autorita, proto ji nainstalujte do prohlížeče na každém počítači, ze kterého aplikace otevíráte. Jinak prohlížeč u každé aplikace ukáže varování.

  1. U serveru otevřete Spravovat Agenta a v části Brána aplikací zvolte Otestovat bránu. Po úspěšném testu se zobrazí otisk certifikátu.
  2. Zvolte Stáhnout certifikát a otisk SHA-256 porovnejte se staženým souborem.
  3. Certifikát nainstalujte podle návodu pro Windows, macOS nebo Firefox v části Jak certifikát nainstalovat.

Agent 0.16 a novější po své aktualizaci obnoví bránu sám. Příkaz Obnovit bránu na serveru je jen pro starší Agenty a nový registrační token nepotřebuje.

Server za VPN nebo doma
Funguje to. Agent navazuje jen odchozí spojení a po nasazení si sám ověří, že aplikace odpovídá. Aplikaci pak otevře jen ten, kdo se na server dostane, tedy typicky kdo je ve stejné síti nebo na stejné VPN.

Odpojení, vyřazení a smazání serveru

U serveru je viditelná sekce Odpojení a smazání se třemi tlačítky:

TlačítkoCo udělá
Odpojit serverInitPad přestane server spravovat a zneplatní jeho přístup. Běžící aplikace zůstanou online.
Vyřadit serverPro server, který rušíte. Historie a adresy zůstanou viditelné a nasazení na něm pak půjde uvolnit.
Smazat serverOdebere server z InitPadu. Na samotném serveru se nic nesmaže.

Odpojený server jde smazat, jen když žádné jeho prostředí neeviduje nasazení. Jinak InitPad ukáže Nejdřív uvolněte nasazení na tomto serveru: …; nasazení uvolníte akcí Uvolnit nasazení, viz Nasazení a prostředí.

Odinstalace Agenta ze serveru

V Spravovat Agenta rozbalte Diagnostika a odebrání, otevřete Odinstalovat ze serveru a příkaz spusťte na serveru. Ověří kontrolní součet instalátoru, odmítne server registrovaný pro jiný cíl, vypíše, co odstraní, a vyžádá potvrzení. Odstraní kontejner Agenta, jeho uloženou identitu a certifikační autoritu InitPadu, kterou pro něj nainstaloval. Sekce je dostupná i pro odpojeného Agenta.

Volba Odstranit i aplikace, které InitPad na tento server nasadil smaže jejich kontejnery a sítě přímo na serveru. InitPad je pak dál zobrazuje jako nasazené, proto je raději odeberte v InitPadu, dokud je Agent připojený. Po odinstalaci Agenta v InitPadu odpojte, nebo server smažte, aby na něj InitPad už nečekal.

5. Nový projekt

  1. Zvolte Nový projekt a zadejte název: malá písmena, číslice a pomlčky.
  2. V poli Vlastník repozitáře na GitHubu vyberte účet nebo organizaci, kde má repozitář vzniknout.
  3. Vyberte Šablonu a Pipeline, tedy která prostředí projekt bude mít: dev, test a prod, jen dev a prod, nebo jen prod.
  4. V části Cíle nasazení přiřaďte každému prostředí server. Jeden server může hostit více prostředí.
  5. Zvolte Vytvořit projekt.

InitPad založí soukromý repozitář s kostrou aplikace, souborem Dockerfile a workflow pro GitHub Actions a nastaví mu potřebné secrety. První běh pipeline začne hned a po jeho dokončení se aplikace nasadí do prostředí dev.

6. Import existujícího repozitáře

Na stránce Nový projekt zvolte Import existujícího repozitáře. InitPad při importu váš kód nemění. Repozitář ale musí splnit tři podmínky a InitPad je před importem sám zkontroluje:

PodmínkaPodrobnosti
DockerfileV kořeni výchozí větve. Čistě statické šablony ho nevyžadují.
Workflow InitPaduPřesně v souboru .github/workflows/ci.yml. Startovní verzi si stáhnete na obrazovce importu a commitnete ji sami.
Název repozitářeMalá písmena, číslice a pomlčky, nejvýše 41 znaků. Stane se názvem projektu.

Projekt, který už má vlastní pipeline

  • Vaše workflow v jiných souborech běží dál beze změny.
  • InitPad čte stav jen z ci.yml. Pokud se tak jmenuje vaše pipeline, přejmenujte ji, nebo kroky InitPadu přidejte do ní.
  • Nasazení spouští jen workflow InitPadu. Když vaše testy v jiném souboru selžou, InitPad to nevidí a nasadí i tak. Testy, které mají nasazení zastavit, patří do ci.yml.
  • Aplikace musí poslouchat na portu zvolené šablony a odpovídat na její kontrolní adrese, jinak nasazení skončí neúspěšnou kontrolou zdraví.

7. Nasazení a prostředí

Push do výchozí větve spustí pipeline. Ta aplikaci otestuje, sestaví image a předá ho InitPadu, který ho nasadí do prostředí dev. Do dalších prostředí se povyšuje přesně tentýž image, nic se nesestavuje znovu.

Co chceteJak na to
Povýšit dev do testuTlačítko se šipkou mezi kartami prostředí.
Nasadit do produkceŽádost o prod. Nasazení musí schválit vlastník, administrátor nebo správce workspace.
Vrátit starší verziNabídka prostředí, Vrátit na předchozí verzi…
Nasadit stejnou verzi znovuNabídka prostředí, Znovu nasadit ověřený build.
Dočasně vypnout aplikaciZastavit a později Spustit.

Přesunout prostředí na jiný serverZměnit cíl. Aplikaci nasazenou přes připojeného Agenta nejdřív odstraňte.
Uvolnit nasazení na odpojeném nebo vyřazeném serveruNabídka prostředí, Uvolnit nasazení. Uvolní se jen záznam v InitPadu, kontejner může na serveru dál běžet a je potřeba ho tam odstranit ručně.
Zjistit, proč aplikace neběžíDiagnostika workloadu… a část Aktivita nasazení.
Zopakovat neúspěšnou pipelineZnovu spustit neúspěšné úlohy na GitHubu.

Kroky pipeline u commitu vedou přímo na logy běhu na GitHubu.

8. Proměnné a secrety

V detailu projektu je část Konfigurace s proměnnými pro každé prostředí zvlášť. InitPad je aplikaci předá při nasazení. Změna se projeví až po opětovném nasazení prostředí.

Hodnoty secretů se ukládají šifrovaně a po uložení už je nikdo neuvidí, ani vy. Secret můžete jen nahradit novou hodnotou, nebo smazat. Vrácení na předchozí verzi mění kód aplikace, proměnné zůstávají aktuální.

9. Tým a role

Projekty, servery i instalace GitHub App patří do workspace. Kromě osobního workspace si můžete založit týmový v nabídce workspace v levém menu volbou Přidat nový workspace. Ve veřejné edici může jeden účet vlastnit nejvýše pět týmových workspace.

Osobní workspace je jen váš. Členy přidáte do týmového workspace v Nastavení workspace (položka Workspace v menu) v části Členové workspace tlačítkem Přidat člena. Zadáte uživatelské jméno nebo e-mail. Dotyčný se musí do InitPadu aspoň jednou přihlásit, jinak jeho účet neexistuje.

Člen workspace má jednu z pěti rolí:

RoleCo smí navíc oproti předchozí
ČtenářProhlížet projekty a jejich stav.
ČlenZakládat a importovat projekty a nasazovat.
SprávcePřidávat servery a schvalovat nasazení do produkce.
AdministrátorInstalovat GitHub App pro workspace a spravovat členy.
VlastníkMěnit pravidlo pro schvalování produkce.

Workspace může vyžadovat, aby produkci schválil někdo jiný než žadatel. Kdo co udělal, najdete v části Auditní log.

10. Přejmenování a smazání

Přejmenování repozitáře nebo organizace

InitPad přejmenování na GitHubu sleduje sám. Projekt si do chvíle převezme nový název a další push se nasadí jako dřív. Kontejner na serveru si ponechá původní jméno, aby se běžící aplikace nepřesouvala.

Převod repozitáře
Převod na jiného vlastníka přejmenování není. Když repozitář přestane být pro instalaci GitHub App dostupný, InitPad ho považuje za smazaný a projekt uklidí.

Smazání projektu

  1. U každého prostředí nasazeného přes připojeného Agenta nejdřív zvolte Odstranit nasazení a počkejte, až úklid doběhne. Nasazení na odpojeném nebo vyřazeném serveru nejdřív uvolněte akcí Uvolnit nasazení, nebo je nechte označit v dialogu.
  2. Zvolte Smazat projekt.
  3. Volbu Smazat také zdrojový repozitář a uvolnit jeho název zaškrtněte jen tehdy, když chcete smazat i repozitář na GitHubu. Bez ní repozitář zůstane a půjde později znovu importovat.

Projekt s nasazením na odpojeném nebo vyřazeném serveru jde smazat taky. Dialog toto nasazení označí server odpojen · zůstane na serveru a vyžaduje zaškrtnout Smazat záznam v InitPadu, i když chráněný úklid ještě čeká. Kontejnery tam mohou dál běžet a je potřeba je na serveru odstranit ručně.

Prostředí, jehož sestavení nebo nasazení selhalo dřív, než se na server cokoli dostalo, úklid nepotřebuje. Projekt s ním smažete rovnou.

12. Omezení veřejné edice

  • Aplikace se nasazují jen na servery s Agentem. Sdílený webhosting přes SFTP veřejná edice zatím nenasadí.
  • Zdrojem kódu je GitHub. Jiné Git servery veřejná edice nepodporuje.
  • Aplikace na serveru za VPN je dostupná jen z té sítě. InitPad ji ven nezveřejní.
  • Workflow InitPadu musí být v souboru ci.yml.
  • Jeden účet může vlastnit nejvýše pět týmových workspace.
